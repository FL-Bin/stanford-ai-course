## 第 5 讲｜10/6：Agent Skills 全解
### 为什么需要 skills
- MCP 适合接入第三方服务；但大模型**特别擅长照着一份较长的流程说明去做事**，把这种能力暴露出来，是代理框架很重要的一部分。
- Skill：一种**按需动态加载**的能力标准——面向特定领域，**把代码和提示词结合起来**，代理需要时才加载。可以把它理解为“给代理用的脚本（scripts for agents）”。
- 常见用途：写文档、做 PPT、数据分析等。

### Skill 的几类（课件分类）
| 类别 | 例子 / 作用 |
|---|---|
| 代码理解与规划 | RePPIT 系列 skill；Matt Pocock 的 grill-me / grill-with-docs（让代理反复追问你，帮你把任务想清楚） |
| 验证（Verification） | 一个专门“生成验证 skill”的 skill，让代理检查自己的产出 |
| 代码风格 | 定义代码层面的最佳实践，适合给代码审查代理用 |
| 其他 | 例如网页解析：用 browse.sh 写 web skill |

### 最佳实践（转述）
1. **范围要小**：一个 skill 只做一件定义清楚的事。
2. **维护自己的 skill 合集**，方便在不同项目间带着走（课件引用了一句比喻：厨师换厨房也带着自己的刀）。
3. **从自己的聊天记录里挖**：skill 本质是用 Markdown 写下的流程——翻翻你和代理的对话，看你在哪些地方纠正过它，这些就是该写进 skill 的东西。
4. **别重复造轮子**：给代理一个 CLI 工具，再用 skill 把样板操作包起来。
5. **写清触发场景**：在说明里写出哪些情况、哪些说法应该触发这个 skill。
6. **渐进式披露（progressive disclosure）**：主文件保持简短，需要时再引用具体文件补充上下文。
7. **模块化、可组合**。
8. **保留一个验证 skill**，让代理检查自己的工作，形成改进闭环。

API / MCP / Skills 三者对比见第 2 周笔记。

## 第 6 讲｜10/8：嘉宾 Lee Robinson ——“常驻代理（always-on agents）是怎么工作的”
> 嘉宾课件标有保密/前瞻声明，这里只概括公开讲到的核心思路，具体实现细节请看官方课件。

- **出发点**：第 1 周写的代理在你关掉终端时就停了。常驻代理运行在服务器上，有自己的云端电脑（小型虚拟机，带桌面、浏览器和文件），会保存状态、记忆和 skills，由事件触发（你的消息、定时任务、Slack、电话、后台任务完成等），可以连续工作几个月。
- **人与 AI 协作方式的演进**：复制粘贴聊天 → 终端里的代理（每步你来批准）→ 多个代理在后台/云端并行（你审最终改动）→ 你给一个有自己电脑、工具和记忆的代理发消息，它在你离开后继续干活。从“逐步批准”变成“随时纠偏（steering）”；模型越强，界面越简单。
- **模型的六项新能力**：长时间工作；把子任务交给有全新上下文的助手代理；使用真实工具（shell、文件、浏览器、MCP）；操作电脑屏幕；把知识存成文件（skills、记忆）；看人演示一遍就把步骤存成 skill。
- **“知识放在文件里”**：记忆和 skills 都是纯文本文件，人和代理都能读、搜、改；skill 只在需要时加载，所以多也不贵。
- **架构要点**：瘦客户端、厚服务器；所有状态存在服务器，虚拟机随时可重建；空闲时休眠、有事件时唤醒；每个会话一次只跑一轮；用**持久化工作流（durable workflow）**而不是简单任务队列，服务器崩了能从断点继续，每一步设计成**幂等（idempotent）**，重试安全。
- **框架设计**：代理的普通文本不直接展示给用户，用专门的“发消息”工具和你说话；没有新进展时可以保持安静。
