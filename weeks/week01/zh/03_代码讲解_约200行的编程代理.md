# 讲义 03｜代码讲解：200 行写一个 Claude Code（claude_code_200lines.py）
运行环境：Python 3.12+（代码里的 f-string 嵌套了同种引号，旧版本会报错），`pip install openai python-dotenv`，`.env` 里写 `OPENAI_API_KEY`。

> 注意：代码里的模型名是 `gpt-5.6-terra`，用 OpenAI 的 Responses API（`openai_client.responses.create`）。你手上没有这个模型的话，把它换成自己能用的模型。

## 整体结构（5 块）
| 模块 | 作用 |
|---|---|
| `SYSTEM_PROMPT` | 系统提示词模板，里面留一个 `{tool_list_str}` 占位，用来填工具说明 |
| 3 个工具函数 | `read_file_tool` / `list_files_tool` / `edit_file_tool` |
| `TOOL_REGISTRY` + 工具描述生成 | 用函数的 docstring 和签名，**自动**生成给 LLM 看的工具说明 |
| `extract_tool_invocations` | 从模型回复里解析出 `tool: 名字({JSON})` 这样的行 |
| `run_coding_agent_loop` | 主循环：读用户输入 → 调模型 → 有工具调用就执行，结果回填后再调模型 → 没有工具调用就输出 |

## 1. 系统提示词（我们的转述）
系统提示词大意：告诉模型它是一个编程助手；列出可用工具（用 `{tool_list_str}` 占位自动填入）；规定要调用工具时**只输出一行** `tool: 工具名({JSON参数})`，JSON 用双引号写成一行；收到 `tool_result(...)` 后继续任务；不需要工具就正常回答。原文请看官方代码链接。
要点：这里**没有用 API 原生的 function calling**，而是靠提示词约定一个文本格式，再自己解析。这样最能看清“工具调用”的本质：**它就是文本协议**。

## 2. 三个工具
- `resolve_abs_path`：把相对路径换成基于当前目录的绝对路径，支持 `~`。
- `read_file_tool(filename)`：返回 `{"file_path", "content"}`。
- `list_files_tool(path)`：列出目录，每项标明 `file` 或 `dir`。
- `edit_file_tool(path, old_str, new_str)`：
  - `old_str` 为空 → 用 `new_str` 新建或覆盖文件（`created_file`）
  - 找不到 `old_str` → 返回 `old_str not found`（**把错误告诉模型，而不是让程序崩掉**）
  - 找到了 → 只替换**第一处**（`replace(old, new, 1)`）
  - 这就是 Claude Code `Edit` 工具“精确字符串替换（exact string replace）”的原型

## 3. 工具说明怎么自动生成
```python
def get_tool_str_representation(tool_name):
    tool = TOOL_REGISTRY[tool_name]
    return f"Name: {tool_name}\nDescription: {tool.__doc__}\nSignature: {inspect.signature(tool)}"
```
（原代码格式略有不同，这里为了易读做了简化。）
→ 对应 9/24 课上的重点：**docstring、参数类型、函数名都会原样进入提示词**，所以 docstring 写得清楚，模型才会用对工具。

## 4. 解析工具调用
逐行找以 `tool:` 开头的行，按 `(` 切开拿到工具名，再用 `json.JSONDecoder().raw_decode` 解析后面的 JSON。格式不对的行直接跳过。

## 5. 主循环（代理循环 agent loop 的核心）
```
conversation = [developer 角色：系统提示词]
外层循环：读用户输入 → 追加 user 消息
  内层循环：
    回复 = 调 LLM(conversation)
    工具调用 = 解析(回复)
    没有工具调用 → 打印回复，追加 assistant 消息，跳出内层循环（等下一次用户输入）
    有工具调用 → 追加 assistant 消息；逐个执行工具，
               把结果用 user 角色、写成 "tool_result({json})" 追加进对话 → 再调 LLM
```
要点：
- 对话列表**只会追加**，这就是“上下文窗口”不断变长的原因，也就是之后要学 compaction（压缩）的原因。
- 工具结果用 `user` 角色回填，跟课上抓包看到的 Claude Code 一样（tool result 也放在 user 消息里）。
