## 从“最小循环”到“完整框架（harness）”
上一讲的代理只有循环和三个工具。真正的产品级代理（如 Claude Code）在循环外面包了一整套**框架（harness）**，讲师认为**框架设计是编程代理最关键的问题之一**。它大致由 8 个部分组成：

| 组成 | 中文 | 我们的一句话解释 |
|---|---|---|
| System prompt | 系统提示词 | 代理的“总说明书”：行为方式、安全护栏、运行环境 |
| Config files (AGENTS.md / CLAUDE.md) | 配置文件 | 用户写给代理的项目说明，优先级高于默认行为 |
| Tool list | 工具列表 | 少而强；工具名、描述、参数签名本身就是提示词 |
| Plan mode | 计划模式 | 先写方案/规格、问清需求，再动手 |
| Subagents | 子代理 | 开一个干净的新上下文去做子任务，只把结论交回来；可并行但更费 token |
| Skills | 技能 | 写好的一套流程（提示词 + 可选脚本），按需加载 |
| Hooks | 钩子 | 在生命周期的固定节点自动跑的代码/提示词，适合前后处理 |
| Compaction | 压缩 | 上下文快满时把历史总结成摘要替换掉；会丢信息（lossy） |

## 好框架的三条原则（转述）
1. **简单**：少量通用而强大的工具（比如 bash、sql）胜过一大堆零碎工具。
2. **守住上下文窗口**：上下文塞太满模型会变笨（讲师称为 “dumb zone”），也要防工具膨胀（tool bloat）。
3. **提示词会一直变**：结构要便于调整和迭代。
